# GKD 比亚迪小组件版（第一版）

入口：GKD → 设置 → 车辆靠近 / 远离。默认不启用，支持 Android 12 及以上。

## 范围

- 靠近解锁、远离上锁，使用已安装的官方比亚迪 App 小组件。
- 不登录比亚迪账号、不调用云控接口、不操作上下电、不迁移原 APK 的壳或 native 库。
- 复用 GKD 的无障碍服务，通过短暂的无障碍悬浮窗承载官方 RemoteViews。
- 蓝牙前台服务与 GKD 在同一应用进程，通知提供停止入口。官方比亚迪 App 仍是必要依赖。

## 配置

1. 在官方比亚迪 App 登录自己的账号并确认当前车辆。
2. 在 GKD 开启无障碍服务；授予附近设备和通知权限。
3. 搜索车辆 BLE 设备（如 BYD BLE3），选择并保存地址。多媒体蓝牙不是控车 BLE；随机地址改变后需重新选择。
4. 绑定官方控车小组件，完成系统授权及比亚迪小组件配置。
5. 分别标记解锁和上锁按钮。预览拦截触摸，标记本身不发送指令；两个按钮必须有不同、唯一的可点击 View ID。
6. 核对车辆实际状态，选择“车已锁，启动”或“车未锁，启动”。首次已锁启动需要先收到远处信号，再检测连续靠近。

阈值为 RSSI dBm，数值越大越近。默认靠近 -80、远离 -90；这两个值是初始配置，不是所有车辆/手机的最佳距离。可根据手机放置位置和实测调整，远离值必须小于靠近值。

## 判断和省电

- 三次有效采样，持续至少两秒才触发；300ms 内重复数据和超过五秒的缓存广播不参与判断。
- 两阈值之间保持当前阶段；十秒以上的采样间隔清空确认计数。
- 点击后的十五秒不触发反向操作，减少人体遮挡引起的快速反复锁/解锁。
- 信号消失、关闭蓝牙、权限丢失不会等价于远离上锁。
- 分段扫描：上锁阶段扫描 6 秒，休息 3 秒。解锁阶段持续扫描以检测远离。
- 静止暂停：上锁阶段静止 30 秒后暂停；唤醒型显著运动传感器负责恢复。没有该传感器时继续扫描。
- 熄屏低功耗：上锁阶段熄屏使用 LOW_POWER，其他阶段 BALANCED。
- 三项可独立关闭；修改配置会停止当前自动判断，须再次确认车况后启动。
- 小组件执行期间持有最长十秒的 CPU 唤醒锁，不持有全天唤醒锁，不申请精确闹钟或 GPS。

第一版尚未实现原版的 GATT 重连扫描、手持/口袋双阈值、Wi-Fi 停扫和围栏。这是同一应用下的功能整合，不能据此宣称已测得耗电下降。

## 结果边界

`performClick()` 返回成功仅表示控件接收点击。软件记录“点击已发出，尚未确认车端结果”，接下来的判断阶段按已发出的命令推进；这不证明车门实际变化。

小组件未渲染、绑定失效、官方 App 版本变化或点击失败会将判断状态置为未知，避免自动重复点击；请停止功能、人工核对车况后重新启动。应用退出、系统杀进程或重启不会自动猜测车辆状态、自动恢复控车。

仅收到持续弱信号才会自动上锁，因此设备突然停止广播时可能无法自动上锁；仍需保留官方 App/实体钥匙的手动操作入口。

纯 JVM 测试覆盖启动状态未知、启动时就在近处、靠近持续确认、重复广播、信号波动、采样间断、执行失败和非法阈值。

构建和测试命令（仅 gkd 渠道）：

```text
./gradlew :gkd-app:testGkdDebugUnitTest :gkd-app:assembleGkdDebug
```

实车验收需用户在场：先核对绑定车辆与按钮，然后检查手持/口袋靠近、远离、驻留、蓝牙关闭、熄屏、vivo 后台限制、官方 App 登录失效及软件重启。锁屏时小组件的 PendingIntent 能否完成操作由官方 App 和手机系统决定，本模块不绕过锁屏认证。
